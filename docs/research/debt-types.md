# 债类型清单：最终分类学

> 票：[债分类学：六维度失败模式如何映射为债的类型 #40](https://github.com/asiazhang/cognicode/issues/40) · 地图：[#39](https://github.com/asiazhang/cognicode/issues/39)
> 输入：[债候选观点集（#46）](./debt-candidates.md)、[既有谱系综述（#45）](./debt-taxonomy.md)、CONTEXT.md 六维度失败模式
> 效力：本清单是最终债类型集合。后续按族判据细则票、DEBT.md 样例票、决策文档票均以此为基准；slug 稳定，后续引用不漂移。

## 摘要

观点集 23 项候选收敛为 **20 个债类型**：1 项拆解（`code-smell`）、2 项合并（`comment-rot`→`doc-rot`、`dep-doc-gone`→`dep-stale`）、1 项出册（`zombie-branch`）、1 项拆解新生（`duplicate-code`）。分类框架为**双层结构**：失败模式做判断轴，债类型（slug）做检测与报告单元，工件族做展示分组标签。

## 分类框架（本票六项框架决策）

1. **产出边界**：本票只出「分类框架 + 最终类型清单」。逐类型判据细则与实例打分 rubric 下放给按族毕业的 grilling 子票。
2. **双层结构**：
   - **失败模式**（沿用 CONTEXT.md 既有术语：可解性 / 变更安全性 / 效率 / 可导航性 / 环境可用性 / 可诊断性）是**判断轴**——一个类型的收录与归属都按「agent 在它上面怎么失败」判定；
   - **债类型**（slug）是检测规则与 DEBT.md 报告行的单元，每个类型标注一或多个失败模式归属，报告按失败模式分组呈现；
   - 工件族（结构/测试/文档/依赖/进程/架构）只做展示分组，借行业通用语降低沟通成本，无判断作用。
3. **收录判据**：唯一标准是「对 AI 不友好」——能否重述为 agent 的具体失败形态（迷路 / 犯错 / 爆炸），且该形态可归入六失败模式之一。**业界好实践不是收录依据**（缩进规范、模式纯度同为好实践但 agent 零利息，出册）。防换皮操作测试：判断轴必须在具体案例上改变过结论（存在「别人说债、我们说不债」与反向的案例）。
4. **G 类可译性**：架构形状债收录前须通过翻译——判据锚点从源体系命题（如 deletion test）换为 agent 失败形态，阈值须能从 agent 失败角度论证。本次三债全部过译（见各条目）。
5. **收录与可检测性解耦**：可检测性（确定性 / LLM 推断 / 混合）是清单标注字段，不是收录门槛——LLM 推断档的设计留给后续票，不在分类学阶段预支淘汰。
6. **严重度依据**：本票每类型给「严重度机制」（通过哪个失败模式、以什么机制伤害 agent）+ 沿用观点集的高/中/低直觉预排（明示为先验，真实分数一律在实例上产生）。出分/排序的聚合形态是后续票。

## 20 类型清单

### A 结构债

| slug | 名称 | 失败模式归属 | 严重度机制 | 预排 | 检测档 |
|---|---|---|---|---|---|
| `dead-code` | 死代码 | 可导航性 + 效率 | agent 分不清「没人调」和「故意留的 API」，在死代码上浪费推理预算甚至修改它。判据方向与人类体系相反（人类零利息、agent 负导航）——差异化类型 | 中 | **MVP 不检测不报告**（#49：检测已被传统工具商品化，委托不自制；类型留册，收录与覆盖解耦） |
| `duplicate-code` | 重复代码 | 变更安全性 | **A 族核心（#49）**：判据锚定唯一真值原则——同一知识存在多份且未声明哪份权威；「改 A 忘 B」是利息而非本金。确定性档（工具集成，jscpd/PMD CPD 类）产文本重复事实（exact / near 两档），LLM 档做语义重复发现（同知识多实现，文本相似度为零的最危险实例） | 高 | 确定性（工具集成，算法选型留雾区）+ LLM（语义重复） |
| `naming-debt` | 命名债 | 可导航性 | agent 靠名字检索代码，命名即检索索引失效。#49 降为低：agent 有完整上下文兜底，命名误读非常规失败来源；确定性档（词典 + 重复符号名）做候选生成，LLM 档判「仅凭名字能否预测符号做什么」，报告排 A 族末位 | 低（原高，#49 调整） | 确定性（候选生成）+ LLM |

A 族判据细则已由 [#49](https://github.com/asiazhang/cognicode/issues/49) 落定：唯一真值升为全方法论判断原则（见 CONTEXT.md 术语表）；dead-code 留册不覆盖；duplicate-code 两档分工（工具集成 + LLM 语义重复）；naming-debt 预排降为低。实例打分维度：duplicate-code 按分叉状态 > 副本距离 > 语义≥文本 > 副本数 > 变化频率，naming-debt 一维（检索误导程度）；多债并存时多 slug 并挂。

补充（同票第二轮）：实例粒度 = 重复簇（N 份副本一个实例，簇内指定权威副本，修复建议挂「其余向权威合并」）；测试代码与产品代码同等优先级（重复重灾区——agent 写测试无法复用样板、token 成本极高，为 duplicate-code 补效率维度痛感机制）；确定性档排除 vendored 目录与生成文件（@generated 标记），语义档全仓扫；语言惯用样板由 LLM 语义档标注降级，不做白名单；naming-debt 语言惯例符号跳过、文件名与符号名同权。

### B 测试债

| slug | 名称 | 失败模式归属 | 严重度机制 | 预排 | 检测档 |
|---|---|---|---|---|---|
| `test-gap` | 测试缺口 | 变更安全性 | 改了没保护的区域，agent 无法自证没炸别处 | 高 | 确定性（提取器需新写，见 #41） |
| `test-rot` | 测试腐烂 | 变更安全性 + 可诊断性 | 假保护：测试在但不测东西，agent 以为安全其实没有 | 高 | 混合 |
| `flaky-test` | 脆弱测试 | 可诊断性 | 随机红绿，agent 误判自己改坏，污染失败归因 | 中 | 确定性（顺序/时间依赖模式） |
| `test-shape` | 测试形状债 | 变更安全性 | 真保护焊死错误对象：测试绕过接口直戳内部，agent 的深度化重构被惩罚（红绿信号撒谎），长期学会不重构。行为学习污染层留二期动态验证，MVP 检测面为形状代理（import 私有符号 / mock 内部依赖） | 中 | 确定性形状代理 + LLM 推断 |

B 族四类型的分野（独立存在的依据）：gap 无信号、rot 假信号、flaky 噪音信号、shape 真信号但带结构性副作用；修复动作也不同（前三者补/修测试，shape 须把测试迁移到接口上，是重构）。

B 族判据细则已由 [#50](https://github.com/asiazhang/cognicode/issues/50) 落定，四项框架决策：

1. **证据等级语言（全 B 族）**：确证信号（实锤证据：保护不存在，如 skip 堆叠、无断言）vs 风险信号（脆性候选：静态反模式命中，未动态验证）——A 族 exact/near 二分的 B 族镜像，贯穿四类型统一使用。flaky 全类型为风险信号档，报告行标注「脆性候选，未动态验证」。
2. **判据方向轴**：test-gap 从源出发看保护（源→测试），rot/flaky/shape 从测试出发看质量（测试→源）——四类型分野在方向轴上再加固。
3. **test-scan 中间产物（术语进 CONTEXT.md）**：一趟「测试→源」扫描产 per-test-file 结构化记录（测试函数计数、skip 标记、断言形态统计、import 私有符号清单、mock 目标清单），作为 rot/flaky/shape 的共享中间层。新语种 = 新增一套语言适配，是工程边界不是判据。
4. **rubric 只锁维度与方向**（#49 先例）：逐类型一维主轴，不设 B 族共享分；权重与阈值留雾区，聚合形态留后续票。

逐类型细则：

- **test-gap**：锚点粒度 = 文件级漏斗 + 符号级精判（第一层筛掉无测试触达文件，第二层对有触达文件做符号级判定；符号级复用 symbols.py 既有资产，coverage 等动态覆盖数据 MVP 不含、选型留雾区）。「测试触达」= 符号触达（被测符号名在测试文件文本中出现即可，不验证调用图——保守口径，确定可提取）。实例粒度 = 每未触达符号一个实例，DEBT.md 报告上卷到模块级一行（gap 符号数/总符号数）。打分主轴 = 裸露度（模块内 gap 符号比例）。
- **test-rot**：三层信号——确定性层（skip 集中度：模块内 skip 占测试函数比例超阈值，约 10%，用比例不用绝对数——绝对数受规模效应影响，那是 monolith-file 的债不是 rot 的；快照债堆叠信号：快照文件计数 + 体量增长，纯文件系统计数）+ LLM 推断层（断言质量：判「被测行为出错时测试会变红吗」——无断言、`assert result` 真值检查、catch-and-pass 均为候选，标置信度）+ 留雾区（快照-实现变更耦合、共编历史、断言 vs 实现过时对比；均需 git 历史或实现对照，成本高）。**断言质量层的理论基准 = 变异性测试**：MVP 用 LLM 静态推断近似（报告必须标置信度，不得伪装实锤）；二期变异性测试做确证 oracle + 校准数据（LLM 判断 vs 突变体存活记录对答案，量化 LLM 层准确率）。快照债边界：rot 的快照信号是时序信号，duplicate-code 的重复是结构信号，同一快照文件可同时挂两 slug。打分主轴 = 假保护率（rot 信号数/测试函数总数）。
- **flaky-test**：静态反模式清单（7 项）：① sleep() 蒙眼等待（等时间而非等条件）② 随机无 seed ③ 时间依赖无注入（now()/new Date() 直接调用）④ 时区/本地化依赖 ⑤ 测试间共享可变全局状态 ⑥ os.environ/cwd 修改不恢复 ⑦ 无 mock 的外部网络调用。清单有界枚举，每语种一套框架级 token 表（Pytest/Jest/Mocha…），新增语种 = 新增 token 表，是工程边界不是判据。动态重跑检测留二期。打分主轴 = 反模式类别数（非计数——计数受模块规模效应影响）。
- **test-shape**：私有符号定义 = 公开面声明优先（__all__ / index.ts 导出表）、语言机制兜底（_ 前缀 / # 字段 / Go 大小写 / Java package-private）。mock 边界判定：mock 公开边界依赖（网络/DB 接口）= 正常测试实践不判债；mock 内部协作对象 = 形状债信号。LLM 档为候选评估器——不做 shape 独立发现，只对确定性候选（import 私有、mock 内部）做「是否真的焊死结构」的置信度评估。行为学习污染层已锁二期动态验证。打分主轴 = private-touch 深度 × mock 内部依赖计数的组合。

两档检测分工总表：确定性档 = gap 符号触达提取（文件级漏斗）、rot 的 skip 集中度 + 快照堆叠、flaky 反模式清单、shape 的 import 私有 + mock 内部目标提取；LLM 推断档 = rot 的断言质量（能变红吗，标置信度）+ shape 的候选评估器（与「LLM 判定进一等公民」种子决策一致）。
### C 文档与知识债

| slug | 名称 | 失败模式归属 | 严重度机制 | 预排 | 检测档 |
|---|---|---|---|---|---|
| `doc-rot` | 文档腐烂（含注释腐烂） | 可解性 + 环境可用性 | 过期书面断言**主动误导** agent（比缺失更糟）；注释块与文档文件是类型内两个检测信号，注释的 agent 触达率更高、作信号级标注 | 高 | LLM 为主 |
| `oral-tradition` | 口头传统 | 可解性 | 关键约定只在人脑里、仓库零痕迹，agent 100% 踩坑且事后无法归因。完全未系统化的空位类型 | 高 | LLM 档压测点 |
| `agent-doc-missing` | 代理上下文文档缺失/撒谎 | 可导航性 + 可解性 | 对 AI 最直接的债：AGENTS.md 等缺失，或存在但过时/与实际冲突 | 高 | 确定性（存在性）+ LLM（过时/冲突） |
C 族判据细则已由 [#51](https://github.com/asiazhang/cognicode/issues/51) 落定，六项框架决策：

1. **检测面聚焦两锚点（MVP）**：文档概念太广，按 agent 触达率只取头部——代理上下文文档（第一信源）+ 代码内注释（读代码必经）。README / docs/ 长文档信号不设计判据，进雾区（doc-rot 类型留册，长文档信号是类型内信号）。doc-rot 的 MVP 判据因此收窄为**注释单通道**。
2. **两层权威附则（唯一真值延伸，已进 CONTEXT.md）**：含义类断言（术语、概念、规则语义）——领域模型文档（代理上下文文档的概念层，如本仓库 CONTEXT.md）若存在则推定权威；行为类断言（可执行事实：命令、路径、函数行为）——代码为事实；行为类冲突只报分叉不裁方向，方向由人裁。
3. **doc-rot 判据 = 注释断言与代码现实的知识分叉**，只判「说了但说错」不判漏说（缺失归 oral-tradition / agent-doc-missing）。三态：断链（确定性档，确证——注释提到的符号/路径/命令/配置键不存在）；语义分叉（LLM 档，风险+置信度+**方向未裁**——对象都在但描述与实现相反，修复建议双写）；单纯过时（LLM 档，风险+置信度——曾真值后漂移）。方向裁定落报告静态标注，MVP 无交互。
4. **oral-tradition 判据 = 应知知识未被 agent 高触达载体（agent 文档 + 注释）覆盖**。两步法：LLM 生成应知清单（概念类/操作类分层）→ 比对指定载体（概念类对照领域模型文档，操作类对照 agent 文档操作层 + 注释）。「文档在但没写这条」= 外化缺口特例记入本类型；概念类缺口另指向 agent-doc-missing 覆盖不足。全类型风险信号档，报告语言「存在性候选」（比 B 族脆性候选再弱一档——连债的存在都是推断）；README/docs 低可达知识接受假阳性（判据锚定 agent 高触达外化，低可达知识对 agent 仍近似未外化）。显式排除 implicit-contract（痕迹在代码里）与 build-entry-unclear（痕迹在文件系统里）可覆盖的缺口。
5. **agent-doc-missing 三态**：存在性（确定性，确证——代理上下文文档清单全缺失；**概念层缺失为置顶档位**，知识的家没建）；过时（LLM，风险+置信度——只扫 agent 文档，判据从严：第一信源误导放大）；冲突（LLM 为主，风险+置信度——多文档互相矛盾或文档-代码相反；裁定规则 = 两层权威附则；多文档并存未声明权威 = 确定性子档，归冲突态不开第四态）。与 doc-rot 边界非重叠：代理上下文文档三态专属本类型。
6. **rubric 只锁主轴与方向（#49/#50 先例）**：doc-rot 主轴 = 误导度（行为反转 > 引用断链 > 单纯陈旧）；oral-tradition 主轴 = 踩坑概率（知识必要性 × 影响面）；agent-doc-missing 主轴 = 误导方向（撒谎 > 缺失，缺失档内置顶概念层缺失）。注释触达率做信号级标注不进主轴。

| slug | 名称 | 失败模式归属 | 严重度机制 | 预排 | 检测档 |

D 族判据细则已由 [#52](https://github.com/asiazhang/cognicode/issues/52) 落定：dep-stale / lockfile-drift 双双留册不覆盖（前者因 web search 普及降利息——失败形态仍在，降级而非除名；后者检测商品化 + 工具报错清晰，唯一真值表述存档备用）；config-drift 为 D 族独苗，判据细则如下。

### D 族细则（config-drift）

1. **判据范围 = 验证回路执行路径上的配置可达性**（路径收口为收录门槛，非排序维度）：只有落在验证回路（构建 + 测试 + 本地运行，见 CONTEXT.md 环境可用性词条）执行路径上被读的配置才进检测面；纯生产/部署路径的配置键无 agent 失败形态，不报。防换皮正向案例：传统 config lint 报所有未定义键（人类运维视角），本类型只报验证回路路径上的（agent 视角）。
2. **两端夹检测**：一端是读取痕迹（env 无默认值读取 + 显式配置文件键；CLI 参数是接口不是环境前提、代码内常量不是配置，均不收），另一端是可见配置源六项（配置模板/默认值文件、CI workflow、agent 上下文文档、README 配置段、compose/基建文件）。病因本身（gitignore 的 `.env`）不可见，只能从两端对撞。compose/基建文件入源清单使「本地 PG 起不来」场景可表达：读取痕迹有 PG 连接配置、六源全无 → 实例。各语言 env 读取语法表留雾区（确定性脚本技术选型）。
3. **三档信号**：C1 读而无源（确定性候选生成，存在性确证；LLM 路径评估器判「是否在验证回路执行路径上」定收录，同 test-shape 的候选评估器结构，标置信度；有默认值的读取不报——不炸，弱信号不占报告面）；C2 多源矛盾（确定性档提取 (键, 值, 源) 三元组，值不同不自动判债，LLM 裁「同语义环境下是否互斥」——localhost vs staging-db 为正当环境差异，同环境两个 DEBUG 才是矛盾；同值多源不报，多份同值的痛感是变更安全机制，归 duplicate-code 家族不在此预支）；C3 文档配置断言（README 等声称的配置 ↔ 代码读取事实双向比对，按失败模式裁不按载体裁——配置断言的失败落点是环境可用性不是可解性，故归本类型不归 doc-rot；README 只划「配置断言」一个切面，长文档其他信号仍留雾区）。
4. **rubric 主轴 = 冷启动阻断度**（只锁方向，聚合形态留雾区聚合票）：无源必需键（直接炸，agent 无法将 KeyError 归因于配置缺失）＞ 多源矛盾（悄悄错，污染后续行为）＞ 文档误导（排障绕路，通常不炸）。
5. **验证回路三轴叙事**（进 #44 决策文档输入）：可启动性（起不起得来，config-drift + build-entry-unclear 覆盖）/ 保真度（跑起来了但在撒谎，PG/SQLite 型环境级假保护——20 类型清单缺口，进雾区，E+F 票 #53 毕业时裁「新类型还是并入 test-gap/test-rot rubric」）/ 延迟（起得来也保真但要排队/依赖外部系统——仓库内部分可检，组织基建部分天然出界）。三轴共同点：**债的利息以 agent 的验证速度计价**——AI 让写代码变便宜，瓶颈后移到验证与理解（#48），验证速度是 AI 时代开发效率的核心变量。

## 变换记录（23 候选 → 20 类型）

- **拆解** `code-smell`：SonarQube 杂货袋不整体入册。agent 相关子集（超长函数/深嵌套/上帝类）并入 `monolith-file`（同机制：上下文溢出）；重复代码独立为 `duplicate-code`；美学子集（缩进、模式纯度）出册。
- **合并** `comment-rot` → `doc-rot`：同一伤害机制（过期书面断言主动误导），注释块与文档文件降为类型内两个检测信号；痛感频率差异在信号级标注消化，严重度本就是实例级判定，不为它开独立类型。
- **合并** `dep-doc-gone` → `dep-stale`：agent 失败形态相同（训练数据过时 API 用法），版本比对与上游文档可达性降为两个检测信号。
- **出册** `zombie-branch`：agent 在 fresh clone / 默认分支上工作，多分支真相不构成常规失败来源，伤害落点是人类协作（#45 对照判 (b)）。若实例打分阶段发现真实痛感，作为新类型重开，不预支。
- **新生** `duplicate-code`：自 `code-smell` 拆解而来，独立机制（改 A 忘 B 制造 bug）值得独立判据与修复建议。

## 非类型（显式记录，防 scope 蔓延）

- **安全债、性能债**：无独立的 agent 作用通道，均通过其他债的机制生效（#46 收敛提示 + #45 对照第 13 行）。
- **命名美学 / 模式纯度类异味**：SonarQube 判债、agent 零利息——判断轴改变结论的正向案例。
- **社会债 / 人员债、需求债、缺陷债、版本分叉治理**：判据与 AI 受损无关（#45 对照 (b) 行），产品文档显式声明排除。
