# 技术债候选观点集（广义）

> 讨论票 [#46](https://github.com/asiazhang/cognicode/issues/46) 的产出。本票刻意不查文献、不定框架——这是工程经验的自由摆桌，与谱系研究票 [#45](https://github.com/asiazhang/cognicode/issues/45)（业界体系收录了什么）互为对照，共同喂给债分类学票 [#40](https://github.com/asiazhang/cognicode/issues/40)。最终锚点：**对 AI 不友好的债**（种子决策已锁）。

## 结构约定

每项字段：

- **slug**：稳定 ID，后续逐债讨论与打分引用它，不随增删漂移；
- **主类/次类**：允许一债多标（Q7）；
- **是什么 / 人类痛 / agent 痛**：两列痛感口径（Q2）；
- **系统化标注**：已被业界体系收录 / 仅口头传统存在 / 完全未系统化（Q3）；
- **AI 痛感预排**：高/中/低直觉预排，仅先验，真实分数一律在实例上产生（Q4、Q8）；
- **实例化定位**：这类债在仓库里以什么粒度出现——实例打分的锚点（Q8：打分对象 = 债实例，按实际问题判定，同一类型不同实例分数差异可以很大）。

类：**A** 结构债 · **B** 测试债 · **C** 文档与知识债 · **D** 依赖与环境债 · **E** 进程与结构债 · **F** 版本控制债 · **G** 架构形状债。

## A. 结构债

### `code-smell` · 坏味道/结构债 — 预排：高

超长函数、深嵌套、上帝类、重复代码。系统化：SonarQube 域经典。
人类痛：维护成本线性恶化。agent 痛：在重复代码上改 A 处忘 B 处直接制造 bug（变更安全性）；超长函数超出有效上下文（效率）。
实例化：函数/类/文件级。

### `dead-code` · 死代码 — 预排：中

没人调用的代码、僵尸路径。系统化：业界收录。
agent 分不清「没人调」和「故意留的 API」，在死代码上浪费推理预算甚至修改它（效率+可导航性）。
实例化：符号级。

### `naming-debt` · 命名债 — 预排：高

`handleData2`、`manager.py` 干三件事。系统化：业界收录（SonarQube 弱）。
agent 靠名字检索代码，命名直接让检索失效（可导航性）。
实例化：符号/文件级。

## B. 测试债

### `test-gap` · 测试缺口 — 预排：高

改了没测试保护的区域，agent 无法自证没炸别处（变更安全性）。系统化：业界收录。
资产盘点（[#41](https://github.com/asiazhang/cognicode/issues/41)）：test_gap 提取器需新写（天级）。
实例化：模块/文件级。

### `test-rot` · 测试腐烂 — 预排：高

测试还在但不测东西：过时断言、被 skip、快照债。系统化：仅口头传统。
比缺口阴险——agent 以为有保护其实没有（变更安全性+可诊断性）。
实例化：测试函数级。

### `flaky-test` · 脆弱测试 — 预排：中

依赖执行顺序、真实时间的测试。系统化：仅口头传统。
agent 一跑就红，误判自己改坏了（可诊断性）。
实例化：测试函数级。

### `test-shape` · 测试形状债 — 预排：中

测试必须绕过接口直戳内部才能测（「interface is the test surface」被违反）。系统化：matt 体系收录。
任何深度化重构都被测试网缠死，agent 学会不重构（变更安全性+可诊断性）。
实例化：模块/测试对级。

## C. 文档与知识债

### `doc-rot` · 文档腐烂 — 预排：高

README 说的命令跑不通，架构文档描述的结构已不存在。系统化：业界弱收录。
agent 优先信文档，直接被带进沟里（可解性+环境可用性）。
实例化：文档文件级。

### `oral-tradition` · 口头传统 — 预排：高

关键约定只在某人脑子里，仓库零痕迹。系统化：完全未系统化。
agent 100% 踩坑且事后无法归因（可解性）。
实例化：仓库级。检测面几乎全靠 LLM 推断档——这本身就是对「两档检测」决策的第一次真实压力测试。

### `agent-doc-missing` · 代理上下文文档缺失/撒谎 — 预排：高

AGENTS.md/CLAUDE.md 不存在，或存在但过时/与实际冲突。系统化：matt 体系收录。
对 AI 最直接的债（可导航性+可解性）。CONTEXT.md 已有「代理上下文文档」术语与产分信号，现成资产。
实例化：仓库级单点。

### `comment-rot` · 注释腐烂 — 预排：高

注释说的是三个月前的行为。系统化：业界弱收录（归入文档债）。
agent 读注释的概率远高于读 docs/，是对 agent 杀伤力最强的文档债（可解性+变更安全性）。
实例化：注释块级。

## D. 依赖与环境债

### `dep-stale` · 依赖陈旧 — 预排：高

老库版本触发 agent 训练数据里的过时 API 用法，写出编译不过的代码（可解性+变更安全性）。系统化：业界收录。
人类痛（升级风险）与 agent 痛（训练截止错位）机制不同。
实例化：依赖项级。

### `lockfile-drift` · 锁文件漂移 — 预排：中

lock 与 manifest 不一致、多个锁文件。系统化：仅口头传统。
agent 复现环境失败（环境可用性）。
实例化：仓库级单点。

### `config-drift` · 配置漂移 — 预排：中

本地能跑是因为某人的 `.env`；配置值散落且矛盾。系统化：仅口头传统。
agent 冷启动失败（环境可用性+可诊断性）。
实例化：配置项级。

### `dep-doc-gone` · 依赖文档消失 — 预排：高

依赖本身不旧，但上游文档没了，agent 训练数据里的用法已失效。系统化：完全未系统化。
判定信号：依赖版本 vs agent 训练截止日期的错位（可解性）。
实例化：依赖项级。

## E. 进程与结构债

### `build-entry-unclear` · 构建入口不明 — 预排：高

要跑测试得先知道「先起 docker 再跑那个脚本」。系统化：仅口头传统。
agent 冷启动失败的第一大来源（环境可用性）。资产盘点：探测定位面可复用。
实例化：仓库级单点。

### `monolith-file` · 巨石文件 — 预排：高

超出 agent 有效上下文窗口的文件，改一行要读五千行（效率+可导航性）。系统化：业界弱收录。
实例化：文件级。

### `implicit-contract` · 隐式契约 — 预排：高

调用方依赖未声明的不变量（「先 init 再用」），代码上看不出来，炸了才知道（可解性+变更安全性）。系统化：学术收录（隐式知识）。
实例化：接口/调用点级。

## F. 版本控制债

### `zombie-branch` · 长期分支 — 预排：低

真相散落多分支，agent 不知道该以哪个为准（可解性）。系统化：完全未系统化。
触发频率低于其他项，保留但降优先。
实例化：分支级。

### `vendored-dep` · Vendored/复制依赖 — 预排：中

改了 vendor 副本永远追不上上游（变更安全性）。系统化：仅口头传统。
实例化：目录级。

## G. 架构形状债

### `shallow-module` · 浅模块债 — 预排：高

接口复杂度 ≈ 实现复杂度，pass-through 薄壳，Leverage 为负。系统化：matt 体系收录。
判定：deletion test。CONTEXT.md「模块深度」判定协议现成（可导航性+效率）。
实例化：模块级。

### `misplaced-seam` · 错位 seam 债 — 预排：中

想改一个行为必须跨多模块编辑（无 Locality），或内部细节泄漏出 seam。系统化：matt 体系收录。
agent 改一处炸一片（变更安全性+可诊断性）。
实例化：seam/模块组级。

### `hypothetical-seam` · 伪 seam 债 — 预排：中

只有一个 adapter 的抽象层，从未换过。系统化：matt 体系收录。
agent 在假抽象上浪费推理，且「可换」是假信号（效率+可导航性）。判据：one adapter = hypothetical seam, two = real。
实例化：接口级。

## 收敛提示（给分类学票）

- 按种子决策，最终以「AI 是否会迷路/犯错/爆炸」为锚点收敛；人类痛列与业界系统化标注是对照面，不是入选标准。
- 安全债与性能债未收编为独立项：讨论中未发现它们对 agent 的独立作用机制——它们都是通过其他债的机制生效。若谱系研究票发现业界的独立收录理由，由分类学票重开。
- 预排为直觉先验，真实分数一律在实例上产生（打分对象 = 债实例，按实际问题判定）。
- G 类三债的判定全依赖 codebase-design 体系判据（deletion test / seam 数 / adapter 计数），需验证其与六维度失败模式语言的可译性，避免「CogniCode 变成 codebase-design 换皮」。
