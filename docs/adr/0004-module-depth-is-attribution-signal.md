# 模块深度为归因信号：LLM 判定不进产分，只做重构建议

CogniCode 的根本目的是帮用户改进代码库、降低其在 AI 时代的 agentic 维护成本，而非给仓库打分。据此，「模块深度」（LLM 判定模块 deep/shallow）定位为可导航性静态面的**归因信号（不进产分）**：判定产出「哪些模块是 pass-through、建议合并/加深」的重构参考清单，供用户自行判断，不参与打分。deep/shallow 的价值在驱动建议（shallow 模块 = agent 要读大量接口才懂一点行为 = 导航与维护成本高），与评分无关；因此 LLM 判定不确定性是特性——当参考处理，不强校验、不要求跨模型对齐、不要求重跑稳定。这是对 #7「产分信号不用 LLM 判质量」的边界确认：模块深度不进产分，故其 LLM 判定不构成对 #7 的例外。

## Considered Options

- **进产分（#13 原案，作为可导航性第 5 个产分信号）**：被否。把一个参考性信号套进打分框架，会误设「跨模型一致 / 重跑稳定 / deep 占比区分仓库」等度量门槛——而这些门槛连动态测量（#6）自己都不要求，且违背 #7「产分信号 = 语言无关、确定性、廉价提取」的原则。
- **用确定性启发式替代 LLM 判深度**：被否。深度是语义属性（seam 是代码里真实存在的接口），无法用 tree-sitter/文件系统级规则确定性提取（#13 已论证），只能 LLM 判定。
