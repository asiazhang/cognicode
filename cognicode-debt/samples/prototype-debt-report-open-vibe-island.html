先修 #2

BridgeServer.swift 巨石（7 agent 处理器家族）

monolith-file · 确证 · 置信度高
位置 Sources/OpenIslandCore/BridgeServer.swift（3226 行 ≈ 30K token） 热点 90 天被改 10 次 修复成本 高（结构性拆分）

为什么是债：单 class 承载 socket 传输 + 命令分发 + 7 个 agent 的 hook 处理器四件套 + 9 个 Pending 待决状态字典。改任一 agent 的 hook 行为需全读 30K token，直逼 agent 有效上下文参考线；跨 agent 待决状态靠隐式约定维持，局部修改极易破坏其他 agent 的状态机。

怎么修：按 agent 拆 HookHandler 模块（Pending 状态聚合为显式类型），传输与 hook 语义分层，分发器只留路由。修复成本高但被踩频率也最高——每支持一个新 agent 都在加深它。

先修 #4

ProcessMonitoringCoordinator 巨石（5 agent 匹配家族）

monolith-file · 风险 · 置信度中

为什么是债：进程 liveness 跟踪 + 5 个 agent 的 uniqueTracked*Session 复制家族 + TTY 认领，与 BridgeServer 同型。家族式复制使 diff 定位困难：agent 改某个 agent 的匹配规则时，其他 agent 的共享不变量是隐形的。
