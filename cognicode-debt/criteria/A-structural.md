# A 族判据：结构债（dead-code / duplicate-code / naming-debt）

> Part of [Wayfinder 地图 #39](https://github.com/asiazhang/cognicode/issues/39) · 来源：[#49](https://github.com/asiazhang/cognicode/issues/49) 判据细则 + [#40](https://github.com/asiazhang/cognicode/issues/40) 类型清单 + [debt-types.md](../../docs/research/debt-types.md)
> 本文件是 A 族分族子代理的完整作业指令。跨族共享约定（证据包 16K 预算、回传 JSON schema、严重度带定档流程）见 [SKILL.md](../SKILL.md)，此处不重复。

## 0. 族概览

| slug | 名称 | 覆盖 | 检测档 | rubric 主轴 | 预排 |
|---|---|---|---|---|---|
| `dead-code` | 死代码 | **留册不覆盖** | — | — | 中 |
| `duplicate-code` | 重复代码 | 覆盖 | 确定性（工具集成）+ LLM（语义重复） | 分叉状态（一维） | 高 |
| `naming-debt` | 命名债 | 覆盖 | 确定性（候选生成）+ LLM | 检索误导程度（一维） | 低 |

全族判断原则：[CONTEXT.md 唯一真值原则](../../CONTEXT.md)（同一知识存在多份且未声明权威即债）——本族 `duplicate-code` 是其最直接的类型化身，且该原则横贯 doc-rot / config-drift 等族，本族执行时只在自己类型上引用，不做跨族判断。

## 1. dead-code（留册不覆盖）

一行带过：检测已被传统工具商品化（vulture / ts-prune 类），委托不自制；类型留册（收录与覆盖解耦）。捡回条件：二期实证发现传统工具在 agent 语境下有未覆盖的失败形态。执行含义：**本族子代理不产 dead-code 实例**。

## 2. duplicate-code（A 族核心）

### 判据

锚定唯一真值原则：**同一知识存在多份且未声明哪份权威**。「改 A 忘 B」是利息而非本金——判据不是「有重复文本」而是「知识存在多份且无权威声明」。

失败模式：变更安全性（改一处忘别处直接制造 bug）+ 效率（测试代码重复使 agent 写测试无法复用样板、token 成本极高）。

### 两档分工

**确定性档（重复检测工具集成，算法不自研）：**

- 工具集成产文本重复事实（jscpd / PMD CPD 类；具体选型与 near 档阈值参数在雾区，见地图，不预设）。
- 两档重复事实：**exact**（逐字相同）/ **near**（近重复，阈值由工具配置）。
- 扫描范围排除：vendored 目录、生成文件（`@generated` 标记）。
- 语言惯用样板（每语种的 idiomatic boilerplate）不建白名单——由 LLM 语义档识别并标注降级。

**LLM 档（语义重复发现）：**

- 判「同一知识、独立实现」——文本相似度为零的语义重复是最危险的实例（工具永远抓不到）。
- 扫描范围为全仓（不排除 vendored/生成物——语义档判断的是知识重复，不是文本重复）。
- 对确定性档产出的 exact/near 候选做语义复核：语言惯用样板标注降级（不报或降档）。
- 输出标置信度。

### 实例粒度

**重复簇**：N 份副本 = 一个实例。簇内指定权威副本（哪份是当前维护的真相），修复建议挂「其余向权威副本合并」。

### 执行协议要点

- 测试代码与产品代码**同等优先级**——测试重复是重灾区（agent 写测试无法复用样板）。
- 报告行须能指出簇内各副本位置与权威副本。
- 多债并存（同一位置同时命中其他族类型）多 slug 并挂，不在此裁。

### rubric 与严重度带提议

主轴 = **分叉状态**（一维）：簇内副本已分叉（内容不一致）＞ 未分叉但无权威声明 ＞ …。其余维度做信号级标注，不进主轴：

- 副本距离（越远越危险：不同模块 > 同文件）
- 语义重复 ≥ 文本重复（语义档命中比 exact 更危险）
- 副本数
- 变化频率

子代理只**提议**严重度带（高/中/低，沿主轴方向），不终裁；主会话单写手按带定档。

## 3. naming-debt

### 判据

agent 靠名字检索代码，命名即检索索引失效（可导航性）。#49 预排降为低：agent 有完整上下文兜底，命名误读非常规失败来源。

### 两档分工

**确定性档（候选生成）：**

- 词典法：高熵命名（`handleData2`、`manager.py` 干三件事类信号）、重复符号名。
- 文件名与符号名同权（都进候选面）。

**LLM 档（判读）：**

- 判「仅凭名字能否预测符号做什么」——能则不报，不能且误导（预测到错的方向）才报。
- 语言惯例符号（如 Python `__init__`、`_private` 约定）跳过。

### 实例粒度

符号/文件级。

### rubric 与严重度带提议

主轴 = **检索误导程度**（一维）：名字把 agent 引向错误方向 ＞ 名字无信息（查不到但不误导）＞ …。预排低，本族报告排在 A 族末位。

## 4. 留册汇总

| slug | 为何不覆盖 | 捡回条件 |
|---|---|---|
| `dead-code` | 检测商品化，委托不自制 | 二期实证发现传统工具未覆盖的 agent 失败形态 |

## 5. 子代理执行协议

- **候选来源**：确定性档 = 重复检测工具输出（duplicate-code）+ 词典/重复符号扫描（naming-debt）；LLM 档 = 对候选复核 + 全仓语义重复发现。
- **中间产物消费**：本族不消费跨族共享工件（test-scan / module-graph 与 A 族无判据依赖；naming-debt 候选可参照 symbols 工件若 SKILL.md 提供了它）。
- **证据包组装**：每个候选实例附簇内各副本（duplicate-code）或符号定义 + 使用点采样（naming-debt），总量 16K 预算内，超预算降采样并在 rationale 声明。
- **输出 schema**：`{slug, location, confidence, rationale, fix_suggestion}` + 提议严重度带。confidence 三档（高/中/低）必填。
