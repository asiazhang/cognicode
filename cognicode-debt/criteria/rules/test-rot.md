# test-rot：测试腐烂

> 判据权威来源：[B-testing.md](../B-testing.md) · 详解文档供人类讨论，子代理执行口径以族文件为准
> 所属族：[B 族：测试债](../B-testing.md) · 失败模式：变更安全性 + 可诊断性 · 预排：高

## 一览

| 证据等级 | 检测档 | 实例粒度 | rubric 主轴 |
|---|---|---|---|
| 确证 + 风险混合 | 混合（确定性两层 + LLM 推断层） | 未单列（test-scan 以 per-test-file 记录，命中测试文件的相关行采样进证据包） | 假保护率（rot 信号数 / 测试函数总数） |

（一览表按族文件第 0 节概览誊写。rot 的证据等级是「确证 + 风险混合」——skip 堆叠是确证、断言质量是风险，这是本类型最需要向人类读者展开的地方。实例粒度一列族文件未对 rot 单列，按第 6 节「命中测试文件的相关行采样」口径理解，见讨论要点。）

## 规则陈述

这条规则说的是：**测试在，但不测东西**——即「假保护」。文件看起来有 400 个测试，agent 改坏代码后跑一遍，全绿。agent 由此得出「改动安全」的结论，而实际上那片绿色一半是 skip 掉的、一半是没有任何断言的、一半是 `assert result` 这种「只要函数不抛异常就过」的真值检查。比没有测试更糟的是：**它提供了假的信号面**——test-gap 至少诚实地报告「这里无信号」，rot 则把「有信号」写在脸上，信号本身是空的。

B 族四分野里 rot 是「**假信号**」：测试→源方向，从测试出发看质量。对 agent 的具体伤害有两层：**变更安全性**——agent 依赖红绿信号自证改动无害，假信号让这个自证机制直接失效；**可诊断性**——当真有测试变红时，agent 需要信任红的原因与被测行为相关，烂测试的红绿没有因果含义。

为什么人类容易漏掉它：假保护不报错、不失败、不产生任何运行时症状，唯一的症状是「出事的时候保护不在」——这是一个只有出事才能观测的负空间。静态扫描把这片负空间显性化，正是这个类型存在的理由。

## 信号与判定

族文件定义**三层信号**，按证据等级分两档：

### 第 1 层：确定性层 · skip 集中度（确证）

模块内 skip 标记占测试函数比例超阈值（**约 10%**）。skip 是静态可见的硬事实（`@pytest.mark.skip` / `test.skip()` / `it.skip()`），这一层是**确证信号**：skip 堆叠 = 保护被显式摘除。

**为什么用比例不用绝对数**：绝对数受模块规模效应影响——一个 800 个测试函数的模块里有 30 个 skip，绝对数不小，但 3.75% 的比例完全在健康范围；而一个 40 个测试的模块里 15 个 skip（37.5%）是重灾区。更要紧的是职责分界：**「模块测试太多导致各种问题」本身是 monolith-file 的债，不是 rot 的**——用绝对数会把规模效应错记到 rot 头上，让两份报告重复计息。

### 第 2 层：确定性层 · 快照债堆叠（确证）

快照文件计数 + 体量增长，**纯文件系统计数**——`__snapshots__/` 目录下文件数、单文件行数，不需要解析任何文件内容。快照测试的特点是「一次生成、无限堆叠、没人回头删」：实现改了快照没跟上（或反过来），快照文件越长越像只写不读的账本。这一层是时序信号，只看增长趋势，不看内容对错。

### 第 3 层：LLM 推断层 · 断言质量（风险信号）

判一个核心问题：**「被测行为出错时，这个测试会变红吗？」**。三类典型候选（由 test-scan 中间产物的断言形态统计筛出，LLM 只对候选做推断）：

- **无断言**：测试跑完被测函数就结束，什么都没验证；
- **`assert result` 真值检查**：只验证返回值「不是 None / 不是 falsy」，被测逻辑算错十倍照样绿；
- **catch-and-pass**：`try: 被测() except Exception: pass`——异常被吞，测试永远绿。

这一层的理论基准是**变异性测试**（mutate 被测行为、看测试是否变红），但 MVP 用 LLM 静态推断近似，所以**必须标置信度，不得伪装实锤**——这是族文件证据等级语言的硬性要求（CONTEXT.md「证据等级语言」词条的 _Avoid_）。报告语言是「风险信号：脆性候选」。二期变异性测试上线后做确证 oracle + 校准数据（LLM 判断 vs 突变体存活记录对答案），量化这一层的准确率。

### 留雾区（MVP 不做）

快照-实现变更耦合、共编历史、断言 vs 实现过时对比——都需要 git 历史或实现对照，成本高，MVP 不进。

### rubric

主轴 = **假保护率**（rot 信号数 / 测试函数总数）——同样用比例消规模效应。报告行按「信号-定位」二段式呈现：skip 集中度、快照堆叠、断言质量候选各自的定位与计数，统一汇入主轴值。

## 实例

### 正例 1：skip 集中度（比例口径）

```python
# tests/test_importer.py —— 模块共 40 个测试函数
@pytest.mark.skip(reason="flaky，回头修")          # 2019 年加的「回头」
def test_import_csv_with_bom(): ...

@pytest.mark.skip(reason="依赖旧版 fixture")
def test_import_xlsx_legacy(): ...

@pytest.mark.skip(reason="TODO")
@pytest.mark.skip(reason="先跳过，等 schema 稳定")   # 双重 skip，同一个函数
def test_import_parquet(): ...
# ... 共 15 个 skip / 40 个测试函数，skip 率 37.5%
```

- 【信号档】确定性档·第 1 层 skip 集中度（test-scan 的 skip 标记统计）。
- 【证据等级】确证信号——skip 堆叠是静态可见的硬事实。
- 【agent 失败形态】agent 重构 importer 的编码探测逻辑，跑测试「40 个测试全过」——它不知道也不去查其中有 15 个是被 skip 的；唯一真正覆盖 BOM 路径的测试恰好就在 skip 名单里。agent 向用户报告「重构完成，测试全绿」，两周后 BOM 文件导入在生产环境全量报错。
- 预期 DEBT.md 报告行：

```markdown
### test-rot · tests/test_importer.py · 置信度 0.97 · 提议带：高
- 信号：skip 集中度 37.5%（15/40，阈值约 10%）——确证信号
- 定位：test_import_csv_with_bom / test_import_parquet 等 15 个 skip 函数
- 提议修复：逐个销账 skip——已修好的恢复、过时的删除、仍需要的转 xfail 带跟踪号
```

### 正例 2：断言质量（LLM 推断层）

```python
# tests/test_report.py
def test_monthly_report(tmp_path):
    report = build_monthly_report(2024, 2)      # 拼聚合、做分页、写文件
    assert report                               # 只验证「返回了东西」

def test_export_json(tmp_path):
    try:
        export_json(build_monthly_report(2024, 2), tmp_path / "r.json")
    except Exception:
        pass                                     # 吞掉一切异常
```

- 【信号档】LLM 档·第 3 层断言质量（test-scan 断言形态统计筛出候选，LLM 判「行为出错会变红吗」）。
- 【证据等级】风险信号——LLM 推断「`assert report` 只查真值、catch-and-pass 吞异常，两者在金额算错十倍时仍然绿」，未做变异性验证。
- 【agent 失败形态】agent 修改 `build_monthly_report` 的月份边界（`range(1, month)` 漏掉当月），两个测试全绿放行；错误静默流入下游报表。agent 后续 debug 时也无法用这两个测试做二分定位——它们的红绿与任何行为错误都无因果关系，反而污染归因。
- 预期 DEBT.md 报告行：

```markdown
### test-rot · tests/test_report.py · 置信度 0.72 · 提议带：中
- 信号：断言质量候选 2 处——assert report 真值检查 + catch-and-pass（风险信号，LLM 推断标置信度）
- 定位：test_monthly_report / test_export_json
- 提议修复：改为对内容做具体断言（分页数、字段值、文件内容反序列化比对）
```

### 正例 3：快照债堆叠（可与 duplicate-code 双挂）

```
tests/__snapshots__/
├── test_renderer.snap      2,340 行   # 2021-03 创建，至今 +1,900 行
├── test_renderer.snap.1    1,120 行   # 命名冲突拆出的副本，八成内容与主文件重复
└── test_export.snap          890 行   # 其中 600 行与 test_renderer.snap 逐字重复
# 快照文件计数与体量持续增长；重构后旧快照从未清理
```

- 【信号档】确定性档·第 2 层快照债堆叠（纯文件系统计数）。
- 【证据等级】确证信号（堆叠事实）——注意确证的是「堆叠」，不是「内容过期」。
- 【agent 失败形态】agent 改渲染器输出格式，`--snapshot-update` 一把全量刷新，把 2,000+ 行里隐藏的真回归连同格式变化一起「确认」进新快照；想 review diff 时，快照间的大段重复让 review 面积翻了倍。
- 预期 DEBT.md 报告行：

```markdown
### test-rot · tests/__snapshots__/ · 置信度 0.9 · 提议带：中
- 信号：快照债堆叠——3 个快照文件共 4,350 行，持续增长（确证信号）
- 关联：test_renderer.snap 与 test_export.snap 存在大段结构性重复，同时挂 duplicate-code
- 提议修复：清理孤儿快照；重复面收敛为共享 fixture 后按行为分片重建
```

### 反例：skip 绝对数多但比例低，不报

```python
# tests/test_api_all.py —— 汇总测试模块，共 820 个测试函数
# 其中 22 个 skip（2.7%），skip 理由多为「依赖内网沙箱，本地跳过」
```

22 个 skip 的绝对数比正例 1 的 15 个还多，但**不报 test-rot**：skip 率 2.7% 远低于约 10% 的阈值。

为什么不报：族文件明确「**用比例不用绝对数——绝对数受模块规模效应影响**」。820 个测试的模块有 22 个环境依赖型 skip，是完全正常的工程实践；把绝对数当判据，惩罚的其实是「模块测试多」这件事本身，而测试多不是 rot 的罪——如果这个模块的体量本身构成问题，那是 monolith-file 的报告行该操心的事（rot 判据里显式写了「那是 monolith-file 的债不是 rot 的」）。这个反例正是「比例 vs 绝对数」分野的存在意义：防止 rot 越界替 monolith-file 计债。

## 边界与相邻类型

- **test-gap**（同族）：gap 问「保护存在吗」（源→测试），rot 问「存在的保护是真的吗」（测试→源）。符号零触达归 gap；触达了但 skip 堆着、断言烂着归 rot。同模块常双挂。
- **flaky-test**（同族）：同从测试出发，但 flaky 是「噪音信号」（随机红绿、信号不可信），rot 是「假信号」（稳定地绿、绿得毫无含义）。一个 catch-and-pass 测试是 rot（永远绿）；一个 sleep 竞态测试是 flaky（有时绿有时红）——「绿得可疑」vs「红绿随机」是判据分界。
- **duplicate-code**（A 族）：**快照债可双挂**。族文件明确：rot 的快照信号是**时序信号**（堆叠增长、只进不出），duplicate-code 的重复是**结构信号**（逐字重复的代码块）——同一批快照文件完全可能既在持续堆叠（rot）、又彼此大段重复（duplicate-code），两行都报，各报各的主轴。这是「多 slug 并挂」的典型合法场景。
- **fidelity-debt**（E 族）：rot 是**断言烂**（信号本身虚假），fidelity 是**断言好但环境假**（信号真实、跑在替身上）。修复动作不同：rot 修断言，fidelity 对齐环境或显式声明替身局限。同模块可并挂。
- **monolith-file**（E 族）：不是直接相邻，但通过「规模效应」发生职责分界——skip/rot 信号一律用比例，规模本身的问题留给 monolith-file。这是防换皮规则：rot 不替 monolith-file 计债。

## 讨论要点

- **10% 阈值的依据**：族文件写「约 10%」，是拍脑袋还是有对标数据？建议 review 时给出参照（如社区惯例或本仓库分布基线），否则不同仓库的「正常 skip 率」差异会让这个阈值失真。
- **实例粒度缺句**：族文件对 rot 没有像 gap 那样明写实例粒度（每 skip 函数一实例？每测试文件一实例？）。第 6 节只说「命中测试文件的相关行采样进证据包」——采样是证据包口径不是报告粒度。本文按「测试文件级报告、信号分列」理解，待 review 确认。
- **假保护率分母**：主轴「rot 信号数 / 测试函数总数」中，skip 数与断言质量候选数直接相加是否合理？一个 skip 的确证信号与一个 LLM 低置信断言候选等权，会让主轴值混入置信度噪音。族文件未做加权说明，建议 review 讨论。
- **快照「体量增长」的测量窗口**：第 2 层信号要求看增长趋势，但没有定义统计窗口（近 N 次提交？近一季度？）——缺句，工程实现时需要补口径。
- **矛盾点候选**：族文件第 0 节称 rot 证据等级「确证 + 风险混合」，而 CONTEXT.md 证据等级语言只定义了确证/风险两档的 B 族镜像——「混合」意味着同一报告行内可能两种限定语并存，DEBT.md 渲染时证据等级列如何呈现（分信号标注）需要单写手纪律里补一条说明。
