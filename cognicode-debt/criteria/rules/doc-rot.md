# doc-rot：文档腐烂

> 判据权威来源：[C-docs-knowledge.md](../C-docs-knowledge.md) · 详解文档供人类讨论，子代理执行口径以族文件为准
> 所属族：C 文档与知识债（[C-docs-knowledge.md](../C-docs-knowledge.md)）· 失败模式：可解性 + 环境可用性 · 预排：高

## 一览

| 证据等级 | 检测档 | 实例粒度 | rubric 主轴 |
|---|---|---|---|
| 断链：确证；语义分叉：风险 + 置信度 + 方向未裁；单纯过时：风险 + 置信度 | LLM 为主（断链态为确定性提取 + 存在性比对） | 注释断言级（每条分叉的知识断言一个实例） | **误导度**（一维）：行为反转 ＞ 引用断链 ＞ 单纯陈旧 |

MVP 判据收窄为**注释单通道**（#51 决策 1）：README / docs/ 长文档信号不设计判据，进雾区（留册）。实例粒度族文件未显式定义，按判据对象（注释断言）取注释级，见「讨论要点」。

## 规则陈述

这条规则说的是：**注释里说了某个断言，而这个断言与代码现实已经分叉**。判据的关键限定是三个字：**只判「说了但说错」，不判「漏说」**——该写没写的缺失归 oral-tradition / agent-doc-missing 管，本类型专治「书面断言主动误导」。

为什么「说错」比「不说」更糟？agent 的工作模式是信任优先：读到注释 `// 该函数线程安全，可在并发环境直接调用`，它会直接据此推理，不再花预算去验证。一条过期断言不是信息真空，是**负信息**——它把 agent 的推理引向错误前提，比没有注释多了一层「已确认」的假象。这就是失败模式里「可解性」（解不出/解错）与「环境可用性」（跑不起环境）的共同来源。

为什么 MVP 收窄为注释单通道？#51 的推理是 agent 触达率：文档概念太广，README / docs/ 长文档 agent 不一定读（触达率低、信号设计成本高），而**代码内注释是读代码的必经之路**——agent 只要打开文件就会看到。检测面按触达率聚焦头部，注释是最高触达的书面断言载体；代理上下文文档（AGENTS.md 类）是另一个高触达锚点，但那归 agent-doc-missing 专属。

方向裁定的特殊规则：遇到「注释与代码相反」，本类型**只报分叉不裁方向**——到底是注释错了还是代码错了，静态扫描无法知道（也许代码才是 bug）。方向裁定落报告静态标注，由人裁；修复建议因此**双写**（改注释或改代码两个方向并列）。这是两层权威附则（唯一真值延伸，已进 CONTEXT.md）在行为类断言上的投影：**代码为事实**，但行为类冲突只报分叉。

## 信号与判定

三态，各态的检测档与证据等级不同：

| 态 | 检测档 | 证据等级 | 判定 |
|---|---|---|---|
| **断链** | 确定性 | 确证 | 注释提到的符号/路径/命令/配置键不存在 |
| **语义分叉** | LLM | 风险 + 置信度 + **方向未裁** | 对象都在但描述与实现相反；修复建议双写 |
| **单纯过时** | LLM | 风险 + 置信度 | 曾为真值后漂移 |

- **断链**（确定性档）：从注释中提取提到的符号名、文件路径、命令、配置键，做存在性比对（依赖符号索引）。注释说「见 `src/legacy/handler.py` 的 `process_batch`」而那个文件/符号不存在了——这是纯客观事实，确证级，不需要 LLM。
- **语义分叉**（LLM 档）：对象都在，但注释描述的行为与实现相反或实质冲突。例如注释说「返回浅拷贝」而实现返回内部引用。这类判定必须 LLM，且只能标风险 + 置信度——「描述与实现相反」是语义判断。
- **单纯过时**（LLM 档）：注释曾是真值，后来代码漂移了——描述不完全是谎言，但已不准确。同为风险 + 置信度，误导度主轴上排最轻。

报告行按主轴排序：行为反转（语义分叉）＞ 引用断链 ＞ 单纯陈旧。修复建议：断链态指向「更新引用或删除注释」；语义分叉态**双写**（「改注释以匹配代码」或「改代码以匹配注释」并列，方向由人裁）；过时态同断链态方向。

## 实例

### 正例 1：断链态（确证）

```python
# src/pipeline/run.py
def execute(stage: str) -> Result:
    """执行指定阶段。阶段定义见 src/legacy/stages.py 的 STAGE_REGISTRY。"""
    ...
```

仓库里 `src/legacy/stages.py` 已在三个月前的重构中被删除，`STAGE_REGISTRY` 全仓检索无果。

- 【信号档】确定性档：注释断链提取 + 符号/路径存在性比对。
- 【证据等级】确证（目标不存在是客观事实）。
- 【agent 失败形态】agent 接到「给 STAGE_REGISTRY 加一个 cleanup 阶段」，按注释去找文件、找不到，开始怀疑自己检索方式有误，反复尝试多种检索策略浪费轮次——可解性损耗；更糟的情况是它凭空新建一个 `STAGE_REGISTRY`，制造出第二份知识源。

```
DEBT.md 报告行（示意）
slug:          doc-rot
location:      src/pipeline/run.py::execute（docstring 第 2 行）
confidence:    高（确证：断链）
rationale:     注释引用的 src/legacy/stages.py::STAGE_REGISTRY 不存在（全仓检索空白）
fix_suggestion: 更新注释指向现行阶段注册位置；若无替代物则删除该句
提议严重度带:   中（主轴：引用断链）
```

### 正例 2：语义分叉态（风险 + 置信度 + 方向未裁）

```python
# src/models/user.py
def clone_profile(profile: UserProfile) -> UserProfile:
    """返回 profile 的浅拷贝，调用方可安全修改返回值。"""
    return profile   # 重构后为了省对象分配，改成了返回原对象……
```

- 【信号档】LLM 档语义判定：对象（函数）在、注释在，但「浅拷贝/可安全修改」与「返回原对象」相反。
- 【证据等级】风险 + 置信度高。**方向未裁**：也许注释曾是对的、代码改坏了（代码是 bug）；也许语义就是改成共享引用（注释该删）。静态扫描不裁，报告标注由人裁。
- 【agent 失败形态】agent 读到注释，放心地对返回值做 `result.tags.append("x")`——**静默污染了原 profile**，测试还全绿（测试也信了注释）。这是最典型的「书面断言主动误导」：变更安全性失败直接由可解性失败引爆。

```
slug:          doc-rot
location:      src/models/user.py::clone_profile
confidence:    中（风险信号：语义分叉，LLM 推断）
rationale:     注释断言浅拷贝可安全修改，实现返回原对象引用
fix_suggestion: 【双写】(a) 改注释为「返回原对象，勿修改返回值」；(b) 或改实现为返回 copy.copy(profile)——方向由人裁
提议严重度带:   高（主轴：行为反转）
```

### 正例 3：单纯过时态（风险 + 置信度）

```python
# src/auth/token.py
# JWT 有效期 24 小时，超时后须走 /refresh 端点续期
def issue_token(user): ...
# 实现里：TOKEN_TTL = timedelta(hours=1)  —— 半年前安全整改把 TTL 改成了 1 小时，
# 注释里的 "24 小时" 没人更新；/refresh 也在同一整改中改名成了 /token/renew
```

- 【信号档】LLM 档：注释断言（24 小时、/refresh）与实现事实（1 小时、/token/renew）比对。其中 `/refresh` 部分同时构成断链（端点不存在），断言拆开各判各态。
- 【证据等级】风险 + 置信度中。
- 【agent 失败形态】agent 写客户端集成代码时按注释实现「24 小时后才刷新」，实际 1 小时就被 401——环境可用性层面的误导，且报错（401）不会指向注释，归因极难。

```
slug:          doc-rot
location:      src/auth/token.py::issue_token（模块头注释）
confidence:    中（风险信号：单纯过时 + 部分断链）
fix_suggestion: 注释更新为 TTL=1h、刷新端点 /token/renew
提议严重度带:   中（主轴：陈旧为主、含一条断链）
```

### 反例：「漏说」不报（归 oral-tradition）

```python
# src/billing/charge.py
def charge_card(card_token, amount):
    """扣款。"""
    ...  # 实现依赖一个从注释、文档里都找不到的约定：
        # 传入的 card_token 必须是「已通过 3DS 验证」的 token，
        # 否则网关在特定卡组下会静默失败——这条知识只在老员工脑子里
```

这条注释**没有说错任何东西**——它说的「扣款」是对的，问题是**该说的没说**（3DS 验证前置条件缺失）。族文件分野规则明文：doc-rot 只判「说了但说错」，缺失归 oral-tradition（应知知识未被 agent 高触达载体覆盖）/ agent-doc-missing。这个反例说明三类型的分野不是形式上的：同一条坏注释，「说错」与「漏说」的修复动作完全不同（前者改对断言，后者补外化载体）。

## 边界与相邻类型

- **agent-doc-missing（同族，零重叠）**：代理上下文文档（AGENTS.md / CLAUDE.md / CONTEXT.md 类）的三态（存在性/过时/冲突）**专属 agent-doc-missing**；doc-rot MVP 只走**注释**通道。同一仓库两边的分野按载体切：注释里的断言分叉归本类型，agent 文档里的归它。唯一例外：多文档冲突同时构成注释分叉时「各挂各的」（族文件明文）。
- **oral-tradition（同族）**：本类型判「说了但说错」，oral-tradition 判「该说没说」（应知差集）。三类型零重叠，一实例只挂一 slug。
- **config-drift C3（D 族）**：README 等**配置断言**与代码读取事实的矛盾归 config-drift——族文件按失败模式落点裁：配置断言的失败落点是**环境可用性**（agent 跑不起环境），故归 D 族不归本类型；本类型注释断言的失败落点是**可解性**（推理被误导）。载体不是分界，失败模式才是。
- **两层权威附则**：含义类断言（术语/概念/规则语义）冲突时领域模型文档推定权威；行为类断言（命令/路径/函数行为）代码为事实、只报分叉不裁方向——本类型遇到行为类冲突全部按此办理。

## 讨论要点

1. **注释单通道的收窄代价**：README「快速开始」里的过期命令对 agent 冷启动同样有误导（agent 常读 README 找入口），但 #51 以触达率为由将其留册。讨论点：二期判据票是否应该把「README 中被 agent 文档/入口声明引用的段落」作为例外切面收回（注意与 config-drift C3 的 README 配置断言切面保持互斥）。
2. **断链比对的符号索引依赖**：断链态的确定性比对依赖 symbols 工件（SKILL.md 若提供）——A 族说自己不消费跨族工件，C 族说注释通道依赖符号索引，两处口径需在 SKILL.md 层面对齐（谁产 symbols、什么格式）。
3. **断言粒度缺句**：族文件定义了三态但没定义「一条注释里多个断言」的拆分规则（正例 3 里 24h 与 /refresh 应拆两条还是合一条）。建议：按可独立修复的断言拆分，否则销账粒度（重跑 diff）会不稳定。
4. **「方向未裁」的报告呈现**：语义分叉态修复建议双写，但 DEBT.md 行格式里 fix_suggestion 是单字段——双写建议的格式（并列两方向 + 「方向由人裁」标注）需要在单写手渲染规则里定死。
5. **误报面**：注释里故意保留的历史说明（「v1 曾如此，v2 起已改」）字面上构成「过时」，但语义上是有意的沿革记录。LLM 档需要「有意的沿革注释不报」的判读惯例，族文件未提及。
