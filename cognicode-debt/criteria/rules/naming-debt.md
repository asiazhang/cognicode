# naming-debt：命名债

> 判据权威来源：[A-structural.md](../A-structural.md) · 详解文档供人类讨论，子代理执行口径以族文件为准
> 所属族：A 结构债（[A-structural.md](../A-structural.md)）· 失败模式：可导航性 · 预排：低（族内末位）

## 一览

| 证据等级 | 检测档 | 实例粒度 | rubric 主轴 |
|---|---|---|---|
| 确定性档只产候选；报与不报取决于 LLM 判读，必标置信度 | 确定性（候选生成）+ LLM（判读） | 符号 / 文件级 | **检索误导程度**（一维）：名字引向错误方向 ＞ 名字无信息 |

（A 族文件未定义 B 族式的「确证 / 风险」证据等级语言；本类型实质全部落在 LLM 判读档，任何报告行都带置信度。）

## 规则陈述

这条规则说的是：**agent 靠名字检索代码，名字是它的检索索引——索引失效或指错方向，agent 就迷路**。

人类读代码是「顺着读」的，看到一个坏名字多看两行就能纠正；agent 的工作方式不同：它接到「找到处理订单退款的代码」这种自然语言任务后，第一动作是按名字做语义检索（文件名、函数名、类名就是被检索的字符串）。如果退款的逻辑住在一个叫 `processData2()` 的函数里，agent 检索不到它，这就是**可导航性**失败——不是解不出，是找不到该解的地方。

判据的两个档位值得分开理解：

- **名字无信息**（较轻）：比如 `handleStuff`——查不到，但至少不会把 agent 领到错误的地方。agent 的兜底是多翻几个文件，成本是效率损耗。
- **名字误导**（较重）：比如一个叫 `getUserByEmail` 的函数实际上做的是「按 email 查用户**并缓存写穿透**」——agent 检索到了、也以为它只是查询，于是放心地在一个写敏感的路径上调用它。这不是迷路，是**被指错了方向**，直接通向错误修改。

**为什么预排低、排 A 族末位**：#49 的决策理由是 agent 有完整上下文兜底——把周边代码读进来之后，多数坏名字的误导会被上下文纠正，命名误读是「非常规失败来源」。换句话说：这是真实存在的债，但利息在六维失败模式里偏低，排报告末位是对的。这也是一个防换皮的例子：人类代码规范视角里「命名不规范」是高频批评项（美学），本类型只报 agent 实际会迷路/被误导的名字（失败形态）。

## 信号与判定

**确定性档（候选生成）**

- 词典法：高熵命名——`handleData2` 这类「动词 + 万物名词 + 数字」的组合、`manager.py` 一个文件干三件事类的信号、重复符号名（同名符号多处定义）。
- **文件名与符号名同权**：都进候选面。`utils.py` 里住着三十个不相关函数，与坏函数名同罪。

确定性档**只产候选，不判罪**——「高熵」只是字面统计，一个叫 `data2` 的名字是否真的害 agent 迷路，要靠 LLM 档判。

**LLM 档（判读）**

- 判「**仅凭名字能否预测符号做什么**」——能则不报；不能且**误导**（预测到错的方向）才报；只是无信息（查得到但不指向任何方向）降一档报或不报。
- **语言惯例符号跳过**：Python 的 `__init__`、`_private` 前缀、Go 的大小写可见性等语言惯例命名不进候选——这些名字承载的是语言协议，不是仓库的知识债。

**证据等级落点**：所有报告行都是 LLM 判读产物，必标置信度；确定性档只负责把候选面从全仓缩小到高熵集合（「无候选不调 LLM」的预算纪律）。

## 实例

### 正例 1：误导型（主轴最重档）

```python
# src/services/account.py
def get_user_by_email(email: str) -> User:
    """按 email 查用户。"""
    user = cache.get(f"user:{email}")
    if user:
        return user
    user = db.query(User).filter_by(email=email).one()
    cache.set(f"user:{email}", user, ttl=3600)
    write_through_index(user)   # 副作用：写穿透更新二级索引
    return user
```

- 【信号档】确定性档词典法可能不命中（名字本身低熵），由 LLM 档判读命中；或命中「manager 干三件事」同类信号（一个 getter 名下藏三件事）。
- 【证据等级】LLM 判读，置信度高。
- 【agent 失败形态】agent 接到「清理僵尸用户索引」的任务，检索到这个函数，名字说是 `get`（读操作），于是 agent 在一个每分钟跑几千次的路径上继续调用它——误导型命名的可怕之处是 agent **确信自己对了**。这是可导航性失败直接演变成变更安全性失败。

```
DEBT.md 报告行（示意）
slug:          naming-debt
location:      src/services/account.py::get_user_by_email
confidence:    高
rationale:     名字预测为纯查询，实际含写穿透副作用；误导方向
fix_suggestion: 改名 split_user_lookup_and_index / 抽出纯查询函数
提议严重度带:   低（预排低、族内末位；主轴内误导型排最高）
```

### 正例 2：无信息型 + 文件级候选

```
src/core/manager.py        # 480 行：会话管理 + 配置加载 + 重试策略，三件事
src/core/manager.py::handle_data(data, flag, opts)   # flag 是 bool，opts 是 dict，无任何语义
```

- 【信号档】确定性档词典法命中：`manager.py` 干三件事类信号 + `handleData` 型高熵命名。
- 【证据等级】候选经 LLM 判读：判「仅凭名字与文件名无法预测入口在哪」，置信度中。
- 【agent 失败形态】「修改重试策略」任务，agent 按语义检索 retry/backoff 全部落空（真实代码住在 `manager.py` 的 `handle_data` 里）——查不到但也没被指错方向，靠通读兜底，成本是效率与轮次预算。

```
slug:          naming-debt
location:      src/core/manager.py（文件级）+ src/core/manager.py::handle_data（符号级）
confidence:    中
提议严重度带:   低（主轴：无信息，不误导）
```

### 反例：语言惯例符号跳过（不报）

```python
class PaymentGateway:
    def __init__(self, api_key): ...      # Python 惯例：构造器
    def _sign_payload(self, payload): ... # 惯例：单下划线私有

# Go：导出与否由大小写承载
func (g *Gateway) Charge(...) {}   // 大写 = 公开 API，名字短是语言协议
```

`__init__`、`_private`、Go 大小写、Java getter 惯例……这些名字的「信息量低」是**语言协议本身决定的**，任何语种的任何仓库都如此，不是这个仓库的债；更重要的是它们不会误导——agent（和人类）都按语言惯例解读它们。族文件明确：语言惯例符号跳过。同理，一个名字平淡但语义准确的 `main` / `run` 也不报——「仅凭名字能否预测符号做什么」的答案是能（预测为入口/执行），不满足判据。

## 边界与相邻类型

- **duplicate-code（同族）**：确定性档的「重复符号名」信号两边都会看到——若重名背后是**重复知识**（两份同构实现），走 duplicate-code；若只是重名但内容无关，是检索时的歧义，走本类型。判据锚不同：知识多份 vs 检索索引失效。
- **agent-doc-missing（C 族）**：「找不到该找的代码」的静态诱因之一是代理上下文文档缺失——文档在、能指路，坏名字的痛感会被兜底；文档缺失 + 坏名字并存时两个失败形态独立成立，多 slug 并挂。
- **doc-rot（C 族）**：注释说错（主动误导）与名字误导是两种载体上的同一种痛；注释断言走 doc-rot 注释通道，符号名走本类型，互不预支。
- **预排位置**：本类型预排低、A 族报告末位。同位置若同时构成更重的债（如巨石文件里的高熵命名），其他类型优先，本类型做信号级补充。

## 讨论要点

1. **「仅凭名字能否预测」的判读边界**：`get_user_by_email` 带缓存副作用算误导，那「带缓存的读」算不算行业内常规语义？LLM 判读容易在「副作用到什么程度才算误导」上摇摆，置信度阈值需要实例校准。
2. **预排低与报告价值的张力**：#49 把本类型降为低的理由（agent 有完整上下文兜底）同时也削弱了修复优先级——团队讨论点：检索误导型（正例 1 那种）是否应该在低预排内单独置顶，因为它能直接演变成错误修改而不只是浪费轮次。
3. **确定性候选词典的语言适配**：高熵命名的字面统计（`handleData2`）高度依赖语言命名惯例（Python 蛇形 / JS 驼峰），词典法是按语种建 token 表还是语言无关统计，族文件未说死，属工程边界留白。
4. **文件级实例的粒度**：`manager.py` 干三件事是文件级候选，但「干三件事」的判定其实是语义活——确定性档只能给体量/符号密度旁证，真正的判读全在 LLM 档。是否需要在候选生成时引入 module-graph（G 族中间产物）的符号密度做旁证，族文件留白（A 族明言不消费跨族工件，naming-debt 只可参照 symbols 工件若 SKILL.md 提供）。
