# test-gap：测试缺口

> 判据权威来源：[B-testing.md](../B-testing.md) · 详解文档供人类讨论，子代理执行口径以族文件为准
> 所属族：[B 族：测试债](../B-testing.md) · 失败模式：变更安全性 · 预排：高

## 一览

| 证据等级 | 检测档 | 实例粒度 | rubric 主轴 |
|---|---|---|---|
| 确证（保护不存在） | 确定性（提取器需新写） | 每未触达符号一个实例；DEBT.md 报告上卷到模块级一行 | 裸露度（模块内 gap 符号比例） |

（一览表按族文件第 0 节概览 + 第 1 节正文誊写。test-gap 是 B 族四个类型里唯一在族文件里显式声明实例粒度的类型。）

## 规则陈述

这条规则说的是：**源代码里有些公开符号，没有任何测试碰过**。它是 B 族四类型里最朴素的一种债——保护根本不存在，而不是保护坏了。

B 族四类型沿「方向 × 信号真实性」分野：gap **无信号**、rot **假信号**、flaky **噪音信号**、shape **真信号但焊死错误对象**。test-gap 从**源出发看保护**（源→测试方向）：拿源代码的符号清单去问「谁在测你」，而不是拿测试去问「你测得好不好」。

为什么这是对 AI 不友好的债：agent 改代码后的唯一自证手段是跑验证回路（构建 + 测试）。改动落在无保护区域时，agent 面前只有两条坏路——要么**过度自信**，改完跑测试全绿就宣称「已验证」，而实际上没有任何测试执行过这条路径，红绿信号是空转的；要么**过度谨慎**，意识到无保护后不敢动，或自己现写测试又引入新的测试债。人类的肌肉记忆知道「这块没测过，小心点」，agent 每次都是冷启动，没有这个记忆，它只能依赖仓库里可提取的信号——本类型就是把「这里没信号」这个事实变成可提取的信号。

证据等级是**确证**：保护不存在是可静态验证的硬事实（符号名在全部测试文件文本中零出现），不依赖任何推断。

## 信号与判定

确定性档（提取器需新写），两层漏斗，从便宜到贵：

1. **文件级漏斗**：先筛出**无测试触达的文件**——整个文件的所有符号都是 gap，一步筛完，不用做符号级分析。
2. **符号级精判**：对**有触达的文件**做符号级判定，复用 symbols.py 既有资产。文件被部分触达不等于全部符号被触达，这一层抓「同文件里的裸露符号」。

**「测试触达」口径 = 符号触达**：被测符号名在测试文件**文本中出现**即可，**不验证调用图**。为什么这么保守：调用图分析是重语言相关的真静态分析，每种语言一套；而「名字出现在测试文本里」是任何语言都能确定提取的事实，且误报方向可控——口径偏宽只会漏报 rot（触而不测的情况让渡给 rot 管，见反例），不会冤枉 gap。coverage 等动态覆盖数据 MVP 不含，选型留雾区。

**证据等级落点**：本类型全档为**确证信号**（保护不存在），报告行不需要「未动态验证」类限定语——确定性提取零命中就是实锤。

**实例粒度**：每未触达符号一个实例；DEBT.md 报告**上卷到模块级一行**（gap 符号数 / 总符号数）。为什么上卷：一个 200 符号模块如果逐符号列行，会淹没整个报告；「12/19 符号无触达」一行已经足够支撑排序与讨论。符号级明细保留在证据包里（16K 预算内，超预算降采样并在 rationale 声明）。

**rubric 主轴 = 裸露度**：模块内 gap 符号比例。裸露度 75% 的模块比 10% 的模块严重——比例不受模块规模效应影响（对比 test-rot 的 skip 判据，见该文档）。

## 实例

### 正例 1：有触达文件里的符号级缺口

```
src/pricing/engine.py            # 模块共 12 个公开符号
├── PricingConfig                # tests/test_pricing.py 有触达
├── apply_discount(...)          # 全部测试文件文本中零出现
├── recalculate_totals(...)      # 零出现
└── ...（其余 9 个符号零出现）

# tests/test_pricing.py 只测了 PricingConfig 的校验逻辑
```

- 【信号档】确定性档·符号级精判——文件级漏斗放行（同文件的 `PricingConfig` 被触达），符号级精判命中 11 个 gap 符号。
- 【证据等级】确证（保护不存在）。
- 【agent 失败形态】agent 调整 `apply_discount` 的四舍五入策略，跑测试全绿，宣称「已验证」——实际上没有任何测试执行过折扣路径；真正炸掉的是三天后生产环境的发票金额。
- 预期 DEBT.md 报告行：

```markdown
### test-gap · src/pricing/ · 置信度 0.98 · 提议带：高
- 位置：src/pricing/engine.py（apply_discount、recalculate_totals 等 11 个符号）
- 证据：确证信号（保护不存在）——模块 12 个公开符号中 11 个无测试触达，裸露度 92%
- 提议修复：优先为 recalculate_totals（金额计算路径）补符号级断言测试
```

### 正例 2：文件级漏斗直接命中

```
src/utils/dates.py               # parse_chinese_date / quarter_bounds / fiscal_year_end ...
# tests/ 全目录文本检索上述符号名：零命中
```

- 【信号档】确定性档·文件级漏斗——整个文件零触达，第一层漏斗一步筛出，无需符号级分析。
- 【证据等级】确证；裸露度 100%。
- 【agent 失败形态】agent 重构 `fiscal_year_end` 的跨年边界逻辑，全绿通过；但没有任何回归参照，连「改前行为是什么」都无法自证——重构等于盲改。
- 预期 DEBT.md 报告行：

```markdown
### test-gap · src/utils/ · 置信度 0.99 · 提议带：高
- 位置：src/utils/dates.py（全部 6 个公开符号）
- 证据：确证信号（保护不存在）——文件级零测试触达，裸露度 100%
- 提议修复：先为 fiscal_year_end / parse_chinese_date 补快照式基线测试再动重构
```

### 反例：符号有测试触达，浅测不报 gap

```python
# tests/test_tax.py
from src.tax import calculate_tax, TaxBracket

def test_progressive_brackets():
    assert calculate_tax(9000, TaxBracket(0, 12000, 0.1)) == 900
```

`calculate_tax` 只有一个用例、只覆盖一条分支，测得确实浅。**不报 test-gap**：符号名在测试文件文本中出现，符号触达成立，保护「存在」——哪怕很薄。

为什么不报：族文件明确定义符号触达为**保守口径**（出现即可，不验证调用图）。「触达了但测得很浅 / 触而不测」不是 gap 的债，是 **test-rot**（假保护）的地盘——把「测得浅」塞进 gap 会让确定性档失去确定可提取的锚点（「够浅」没有静态判据），而且会把两个修复动作不同的类型搅在一起：gap 补测试、rot 修测试。

## 边界与相邻类型

- **test-rot**（同族，方向相反）：gap 从源出发问「有没有保护」，rot 从测试出发问「保护是不是真的」。同一模块完全可能双挂——一半符号零触达（gap），另一半被触达的符号断言全烂（rot）。分野规则：**触达与否归 gap，触达之后的测试质量归 rot**。
- **fidelity-debt**（E 族）：同模块可并挂。gap 说「这块没测试」，fidelity 说「那块有测试、全绿，但跑在替身环境上」。一个模块可能同时有无保护区域（gap）和环境级假保护区域（fidelity），两行都报。
- **test-shape**（同族）：基本无交叠。shape 判的是「有真保护但焊死内部结构」，前提是保护存在——而 gap 的前提是保护不存在。同一符号不会同时挂两 slug。
- **coverage 留雾区**：符号触达是文本口径，动态 coverage 数据（哪些行真的被执行）MVP 不含。两者会 disagree 的场景（import 了但从未调用）按文本口径判触达，不升级为 gap。

## 讨论要点

- **符号触达宽口径的灰色地带**：`from x import _make` 只 import 未断言——触达成立不报 gap，但它是否应自动作为 rot 断言质量候选喂给 LLM 档？族文件对「gap 提取器与 rot LLM 档的候选衔接」没有明说，建议 review 时补一句。
- **coverage 动态数据进不进二期**：族文件标为选型留雾区。动态数据能消灭「import 未用」的假触达，但引入运行成本与语言相关的覆盖率工具链——与「token 表是工程边界」先例有张力。
- **上卷阈值缺句**：上卷到模块级一行后，「1/19 符号无触达的模块」报不报？族文件只定义了粒度没定义收录线（裸露度多低不进报告），目前只能靠严重度带排序自然沉底，建议 review 定一个收录下限。
- **非公开符号是否计入分母**：「gap 符号数 / 总符号数」的总符号口径（仅公开符号还是含私有）族文件未明说，按 symbols.py 既有资产的公开符号清单理解，待确认。
